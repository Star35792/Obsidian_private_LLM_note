# 开发共识（2026-08-18 定稿）

本文记录插件实现前经过三轮问答对齐的全部决策。与其他文档冲突时，本文档优先于纯工程实现细节，但不覆盖[规格说明](./规格说明.md)的产品边界。

## 目标与范围

- 按本目录文档实现 Obsidian 插件 **AI 笔记助手**。
- 插件 id：`ai-note-assistant`（发布后不可更改）；界面文案全中文。
- **垂直切片先行**：第一开发周期只做「整理 + 文本 diff 写回预览 + 双链建议」，含真实模型接入。
  - 挑战模式、澄清、行动化、捕捉动作，以及新建/移动/归档等变更工具，在切片走通后迭代。
- 切片完成标准：切片走通 + 规格说明中与切片相关的验收条目通过。

## 工程基线

- 在仓库根目录改造 `obsidian-sample-plugin-master`，插件即仓库主体（不再单设 `plugin/` 子目录）。
- 测试框架：**Vitest**。
  - 纯计算模块（`core/`、`linking/`、`changes/`）严格 TDD（red-green-refactor）。
  - UI 和 Obsidian Adapter 层不写自动化测试，靠规格中的验收场景手动验收。
- Git：每完成一个开发步骤且测试全绿就提交一次，Conventional Commits 风格 + 中文描述。
- 调试环境：仓库内建 `dev-vault/`。
  - 入库内容：fixture 笔记（同名消歧、已有链接、反向链接场景）+ 启用本插件的最小 `.obsidian` 配置。
  - 构建产物（`main.js` 等）gitignore，由 sync 脚本同步到 `dev-vault/.obsidian/plugins/ai-note-assistant/`。
- 边栏 UI：原生 TypeScript + Obsidian `ItemView`，**不引入 React**。

## 关键设计决策

- **模型输出契约**：模型返回 **JSON** 结构化 Proposal，插件端 schema 校验（ProposalValidator）后由插件渲染为给用户看的 Markdown。
  - 双链插入位置**不让模型给行号/偏移**；模型给出建议锚点句子，插件在源文中定位计算 `insertion` 范围。
- **版本校验**：`expectedRevision` 使用**内容哈希**——生成预览时对源文算 hash，apply 前重算比对，不一致则计划失效（不用 mtime）。
- **LinkContext 默认数量**：本地候选上限 20 篇，交给模型的候选片段上限 8 篇，最终建议展示上限 5 条，仅展示 high/medium 置信度。三个数字全部做成设置项，默认值如上。
- **远程模型隐私**：设置页总开关默认关闭；每会话首次使用时确认一次，之后会话内直接发送；发送范围始终在边栏可见；API Key 只存 Obsidian 设置存储。
- **写回预览**：文本级 diff（新增绿色、删除红色删除线）。
- **写回位置**：默认追加到笔记末尾，可选替换选区（有选区时）或复制到剪贴板；原始内容默认保留。

## 落地顺序（对齐插件设计.md 第 7 节，收窄到切片）

1. **骨架**：根目录改造 sample → manifest（`ai-note-assistant`）+ 设置页（远程开关/地址/模型/密钥/LinkContext 数量）+ 空边栏视图 + Vitest + dev-vault 同步脚本。
2. **领域类型 + ChangePlan**（TDD）：TextChange、内容哈希版本校验、最小替换、失败回滚——内存 Vault Adapter。
3. **Obsidian Vault Adapter** 接入 + 文本 diff 预览视图 + 写回打通（先用手写假 Proposal 端到端验证）。
4. **LinkContext**：MetadataCache 候选收集、同名消歧、已有链接去重（TDD + dev-vault fixture 验收）。
5. **模型接入**：ModelPort + OpenAI-compatible Adapter + 整理动作的 JSON 契约 + ProposalValidator + 发送范围展示。**此步需要用户提供可用的 API Key**。
6. **双链建议**：模型判断关系 → 逐条确认 → 原生 Wiki Link 写回。
