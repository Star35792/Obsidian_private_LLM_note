# Obsidian 插件实现约束

本页把 AI 规格落到 Obsidian 插件的工程边界，避免提示词设计和实现脱节。

## 生命周期

- `main.ts` 只负责插件加载、卸载和命令注册。
- AI 调用、笔记解析、预览和写回应拆分到职责明确的模块。
- 所有事件、DOM 监听器和定时器都使用 Obsidian 的 `register*` 方法清理。

## 文件操作

- 默认操作当前文件或用户选中的文本。
- 批量操作必须有明确的用户选择和预览。
- 写回前保存原文快照，失败时不得留下半截内容。
- 不读取插件目录之外的系统文件。
- 文件工具只能接收 Vault 相对路径，并拒绝 `..`、绝对路径和符号链接逃逸。
- AI 只能生成 `ChangePlan`，实际文件操作必须由用户确认后的 `applyChanges` 执行。
- 新建前检查同名文件夹或笔记；修改前检查版本；移动前检查目标冲突。
- 删除功能使用可恢复的 Obsidian trash，并默认关闭批量删除。
- 使用 Obsidian `MetadataCache` 获取链接关系，不扫描并维护第二份全库关系数据。
- 插入正向 Wiki Link 后，由 Obsidian 原生索引派生反向链接。
- 同名目标必须通过路径消歧，已有链接不得重复写入。

## 配置与模型

- 完整 API 端点、协议格式、模型名称和密钥放在设置页，不硬编码。
- API 端点必须按用户输入原样请求，禁止自动追加 `/v1`、`/chat/completions`、`/responses` 或修改查询参数。
- Chat Completions 与 Responses API 使用各自的请求体、普通响应解析和 SSE 事件解析；设置格式必须与服务端点匹配。
- 设置加载使用 `loadData()`，保存使用 `saveData()`。
- 默认不开启不必要的网络请求；远程模型必须有清晰的开关和说明。
- 请求超时、取消和错误状态要能回到可编辑的笔记界面。
- 优先流式展示模型可见输出；流式能力不可用时可以回退普通响应，但界面必须明确显示已经回退。
- 过程面板只展示可核对的处理阶段、结构化草稿和整理依据，不要求或伪造隐藏思维链。
- 思维挑战的会话状态只在内存中维护；暂停、取消和插件卸载都不能改写源笔记。

## UI 约束

- 命令名称使用“捕捉想法”“整理当前笔记”“澄清当前想法”“生成下一步”等用户能理解的动词。
- 预览区同时展示原文和建议结果，提供追加、替换、复制和取消。
- 加载状态不能阻塞用户继续编辑原笔记。
- AI 生成内容必须与用户内容有明确视觉区分。

## 构建与发布

- 使用 TypeScript 和 esbuild，生成的 `main.js` 不提交到源码仓库。
- 发布包只包含 `main.js`、`manifest.json` 和需要的 `styles.css`。
- 插件 ID 一旦发布不可更改。
