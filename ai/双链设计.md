# 双链设计

## 1. 双链的含义

双链是一条由源笔记指向目标笔记的显式关系：源笔记保存 `[[目标笔记]]`，Obsidian 根据该正向链接派生目标笔记的反向链接。

插件只写入正向链接，不在 frontmatter、隐藏文件或独立数据库中重复保存反向链接。Obsidian 的 Markdown 文件和 MetadataCache 是事实来源。

## 2. 设计准则

### 关系优先于相似

- 只有当两条笔记存在可说明的关系时才推荐链接。
- 关键词相同、语义相似或同时出现，只能作为候选信号，不能作为最终理由。
- 推荐理由应使用关系语言，例如“支持”“反驳”“解释”“依赖”“延伸”或“提供例子”。

### 上下文优先于链接数量

- 链接应放在能读懂关系的句子中，避免孤立堆放 `[[链接]]`。
- 默认建议修改最小范围，不为追求图谱密度批量插入链接。
- 一个高质量链接优于多个弱相关链接。

### 原生格式优先

- 使用 Obsidian 原生 Wiki Link：`[[笔记]]`、`[[笔记|显示文本]]`、`[[笔记#标题]]` 和 `[[笔记#^块标识]]`。
- 保留用户现有的链接样式、别名、标题链接和块链接。
- 不引入只有本插件才能解析的链接语法。

### 链接粒度与观点一致

- 关系指向整篇笔记时使用笔记链接，指向局部观点时优先使用标题或块链接。
- 不为了获得更多链接而自动拆分笔记；只有用户确认一个观点值得独立发展时才建议创建新笔记。
- 链接文本应放在解释关系的上下文中，使用户不打开目标也能理解为什么链接。

### 用户确认优先

- AI 只产生建议，不自动写入链接。
- 每条建议必须展示目标、关系、依据和插入位置。
- 用户可以逐条接受、拒绝或修改显示文本。

## 3. 领域模型

### 笔记引用

```ts
type NoteRef = {
  path: string;
  title: string;
  aliases: string[];
};
```

`path` 是消除同名歧义的稳定定位信息；`title` 和 `aliases` 用于展示和生成符合用户习惯的链接文本。

### 关系建议

```ts
type LinkSuggestion = {
  target: NoteRef;
  relation: 'supports' | 'contradicts' | 'explains' | 'depends-on' | 'extends' | 'example-of';
  reason: string;
  evidence: Array<{ path: string; excerpt: string }>;
  insertion: { from: number; to: number; text: string };
  confidence: 'high' | 'medium';
};
```

`reason` 面向用户解释关系，`evidence` 让用户能够核对，`insertion` 用于生成可预览的最小改动。首版不展示低置信度建议。

## 4. 候选发现流程

```text
当前选区或笔记
  -> 读取本地链接与标签上下文
  -> 本地筛选少量候选笔记
  -> 提取候选笔记的必要片段
  -> AI 判断关系类型并给出依据
  -> 去重、消歧和阈值过滤
  -> 用户预览并确认
  -> 写入原生 Wiki Link
```

本地筛选在 AI 调用之前完成。插件不得为了寻找关联而把整个库发送给远程模型。

候选信号按优先级排列：

1. 当前笔记已有的出链和入链邻居。
2. 共享明确实体、概念或用户标签的笔记。
3. 最近由用户选中过的相关笔记。
4. 本地全文检索得到的高相关候选。

首版不引入向量数据库。后续只有在本地全文与图关系无法满足召回时，才单独评估本地向量检索。

## 5. 解析与消歧

- 已有完全相同的目标链接时，不重复建议。
- 同名笔记存在多个目标时，展示路径并要求用户选择。
- 未解析链接可以保留，但 AI 不应自动创建对应文件。
- 目标不存在时，只能建议“创建新笔记”；创建动作与插入链接分开确认。
- 链接目标重命名交给 Obsidian 原生文件管理和链接更新机制处理。

## 6. 写回约束

- 插入前校验源文件自生成建议后是否发生变化；发生变化时重新计算预览。
- 每条链接作为独立变更，可单独接受或拒绝。
- 写回只修改预览中展示的范围。
- 写回失败时保持源文件完整，不留下半个链接或不完整 Markdown。

## 7. 首版验收场景

1. 当前笔记与一篇已有笔记存在明确支持关系，插件给出目标、理由和两侧依据。
2. 用户接受建议后，源笔记出现正确 `[[目标]]`，目标笔记的原生反向链接面板出现来源。
3. 同名笔记存在歧义时，插件要求选择路径，不自动插入。
4. 当前笔记已经链接目标时，不产生重复建议。
5. 用户拒绝建议后，任何文件都不发生变化。
