# 权限与确认规范

本文定义 AI 在 Note_Edit 开发和运行时可以自动执行的动作、必须生成计划的动作，以及必须向用户确认的动作。权限按操作的可逆性、外部影响和数据敏感度判断，不能因为过去曾经批准过一次就永久放宽。

## 权限级别

| 级别 | 典型动作 | 默认行为 | 必须留下的证据 |
| --- | --- | --- | --- |
| P0 只读 | 读取项目文档、源码、测试、Git 状态；搜索 Vault 元数据 | 可自动执行 | 事实清单或工具结果 |
| P1 本地可逆 | 编辑源码和文档、运行测试、构建、lint | 在用户任务范围内可执行 | diff、测试结果 |
| P2 外发请求 | 向远程模型发送笔记或代码片段、调用有费用的外部 API | 每次会话明确范围后执行 | 发送范围、目标服务、结果 |
| P3 变更计划 | 生成 `ChangePlan`、计算 diff、检查版本和路径 | 可自动生成，不落盘 | 计划 ID、操作、差异、风险 |
| P4 写回或破坏性动作 | 应用写工具、覆盖笔记、移动、归档、删除、推送、改共享系统 | 逐项确认；未确认不得执行 | 用户确认、结果或取消原因 |

## 开发任务授权

- 用户明确要求“开发/修复/测试”时，AI 可以在仓库内执行 P0、P1，并按 pipeline 更新文档。
- 用户明确要求“提交 Git”时，可以创建本地新提交；只暂存本次任务相关文件，不自动纳入其他未提交修改。
- `git push`、创建或评论 PR、修改 CI/CD、删除分支、覆盖用户未提交工作，必须单独得到明确授权。
- 不修改 Git 配置，不使用 `--no-verify`，不通过 `reset --hard` 或 `checkout` 丢弃工作。

## Vault 与模型边界

- 模型只能看到当前任务必要的上下文；默认不读取整个 Vault。
- 只读工具可以调用，但仍受 Vault 相对路径、范围、数量和返回大小限制。
- 写工具调用即计划：引擎拦截并生成 `ChangePlan`，用户确认后才调用 Adapter 落盘。
- 计划应用前重新检查源文件版本、目标冲突和路径；过期计划必须重新生成。
- 归档使用可恢复 trash；不存在“永久删除”工具。
- API Key、Authorization 头、隐藏思维链和无关文件不得写入日志、memory 或发送到外部模型。

## 暂停条件

遇到以下情况暂停并澄清，不用猜测或反复重试：需求会改变架构或数据边界、文档与代码事实冲突、目标路径不明确、存在同名/覆盖风险、工具权限被拒绝、测试失败原因不明、操作会影响仓库外或共享系统。

## 审计记录

每个开发周期在 [当前计划](../work/当前计划.md) 中维护任务状态，在 [开发记录](../work/开发记录.md) 中记录日期、变更、验证和提交。memory 只保存稳定规律，不替代审计记录。
