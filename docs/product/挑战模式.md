# 思维挑战模式

## 1. 功能定位

思维挑战不是辩论，也不是让 AI 证明用户错了。它的目标是帮助用户看清一个想法的边界、依据和风险。

普通整理回答“我在想什么”；思维挑战继续追问“我为什么这样想”“什么情况会推翻它”“下一步怎样验证”。

## 2. 会话体验

1. 用户从当前选区或当前笔记启动“挑战当前想法”。
2. AI 先提取一个核心主张，并让用户确认是否挑战它。
3. AI 一次只显示一个问题，用户回答后继续。
4. 用户可以跳过问题、暂停、结束，或切换为整理模式。
5. 会话结束时生成摘要预览，用户确认后才写回笔记。

### 强度

| 强度 | 行为 | 适用场景 |
| --- | --- | --- |
| 轻度 | 重点澄清概念和事实，最多 3 轮 | 快速检查一个想法 |
| 标准 | 加入假设、依据和反例，最多 6 轮 | 日常思考整理 |
| 深入 | 持续检查范围、取舍、风险和失败预演 | 重要决定或复杂方案 |

强度只影响问题深度，不改变“每次一个问题”和“用户可以随时停止”的约束。

## 3. 问题策略

问题选择顺序不是固定清单，而是根据当前回答选择最能减少不确定性的一类：

- 概念澄清：关键词能否被具体定义？
- 证据追问：这个判断有什么观察、数据或经历支持？
- 隐含假设：哪些前提没有被说出来？
- 反例：什么情况会让这个结论不成立？
- 范围边界：这个结论适用于哪些情况，不适用于哪些情况？
- 取舍：为了得到这个结果放弃了什么？
- 失败预演：如果最后失败，最可能的原因是什么？

每个问题都附带简短的提问目的，例如“这个问题用于检查你是否把一次经历推广成了普遍规律”。

## 4. 会话状态

```ts
type ChallengeState = {
  sessionId: string;
  source: NoteSource;
  intensity: 'light' | 'standard' | 'deep';
  claim: string;
  turns: Array<{
    category: string;
    question: string;
    answer?: string;
    skipped: boolean;
  }>;
  status: 'waiting' | 'paused' | 'completed' | 'cancelled';
};
```

会话状态只在插件运行期间保存即可。用户确认写回后，摘要才进入 Markdown；取消会话不修改源笔记。

## 5. 结束摘要

```markdown
## 思维挑战摘要

### 当前主张

### 支持依据

### 未验证假设

### 反例与风险

### 相关笔记

### 下一步验证

- [ ] 
```

“相关笔记”使用双链建议的预览结果，关系必须标注为支持、反驳、解释、依赖、延伸或例证之一。

## 6. 验收场景

- 启动后 AI 不直接连续输出一串问题，而是等待用户回答当前问题。
- 用户回答“我不知道”时，AI 可以降低问题难度或允许跳过，不把它当作事实。
- 用户结束会话后，摘要保留已回答内容和未解决问题。
- 用户拒绝写回时，原始笔记和现有双链完全不变。
- 挑战过程中发现的相关笔记只能作为建议，接受后才插入原生 Wiki Link。
