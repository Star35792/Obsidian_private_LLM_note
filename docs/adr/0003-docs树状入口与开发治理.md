# 文档树状入口与开发治理

## 状态

已接受（2026-08-18）。

## 背景

原有 `ai/` 是平铺目录，既承担产品规格、工程约束，也承担动态实现状态。随着文档、memory 和开发任务增加，缺少唯一入口、权限规则、当前计划和时间记录会导致 AI 读错上下文、重复工作或在未确认边界下继续修改。

## 决策

采用树状文档体系，并把 `docs/README.md` 设为唯一默认入口：

- `product/` 保存用户目标、交互协议和领域行为；
- `engineering/` 保存模块设计、工程约束和动态实现状态；
- `process/` 保存 AI 开发流水线和权限与确认规范；
- `work/` 保存当前计划、完成清单和按日期的开发记录；
- `memory/` 保存跨会话可复用的稳定经验；
- `adr/` 保存真实取舍形成的架构决策。

原 `ai/` 下的文档全部迁入上述分支并删除旧入口。文档通过相对链接引用，根入口只做导航，按任务渐进式披露。

开发任务必须经过：阅读上下文、需求澄清、方案切片、代码开发、测试验证、更新 memory、Git 提交。权限按 P0-P4 分级；写工具、外发请求和共享系统操作不能因历史授权而自动放宽。

## 取舍

- **继续平铺**：查找成本低，但入口和职责会随文档数量增长而模糊，无法区分当前状态与稳定约束。
- **按产品/交互/工程拆成更深层级**：层级过深会增加导航成本；本次先采用少量稳定分支，只有分支继续膨胀时才增加子树。
- **把计划和记忆混在一起**：恢复方便但会污染长期记忆；因此计划/时间记录放 `work/`，稳定规律放 `memory/`。

## 后果

- 新文档必须从 `docs/README.md` 可达，不再往 `ai/` 写入。
- 每个开发周期都有可见的计划、完成清单和日期记录。
- 旧的 `ai/` 路径引用必须在迁移时修复；发现旧引用视为文档验证失败。
- 当前实现状态仍是动态文档，不能替代测试和 Git 事实。
