## 2026-08-19：改为按需获取笔记上下文

- 变更：Agent 对话不再预读并外发活动笔记全文；首轮仅提供用户请求和活动路径，模型通过 `searchNotes` 获取有界关键词片段，确有需要时再调用 `readNote` 全文。
- 交互：首次确认弹窗明确首轮发送范围；侧栏处理过程显示搜索、全文读取、链接上下文和编辑预览等工具调用；运行时活动路径不写入持久会话历史。
- 写回边界：编辑仍必须由 `updateNote` 生成带版本校验的 `ChangePlan`，确认后才落盘。
- 验证：30 个测试通过，build、lint 和 `git diff --check` 通过。
- 未纳入：固定“整理”动作仍保留原有整篇发送流程，本次只调整自然语言 Agent 对话。

## 2026-08-19：借鉴 Kimi Code 的精确编辑与上下文压缩

- 变更：新增 `editNote` 精确编辑工具；旧文本默认必须唯一匹配，重复匹配需显式 `replace_all`，编辑计划沿用 `ChangePlan` 的预览、源版本校验和确认写回。
- 变更：`AgentLoop` 增加可配置历史消息上限与持久压缩摘要，超限时保留摘要和最近消息；默认摘要保留被裁掉区间的首尾用户请求并合并早期摘要，且不会作为临时运行上下文发送，也不会因下一轮过滤普通系统提示而丢失。
- 借鉴边界：只采用 Kimi Code 的精确替换、上下文压缩和持久状态标记思路，不引入其 DI、权限或通用 CLI 文件系统模型。
- 验证：项目 `tests/` 目录 8 个测试文件、38 项测试通过；`npm.cmd run build`、`npm.cmd run lint` 和 `git diff --check` 通过。根目录 `npm.cmd test` 会同时发现 `kimi-code-main` 的独立测试；其中失败来自该参考仓库的 Windows/临时文件环境，不作为 Note_Edit 验收结果。

## 2026-08-19：持久化并恢复 Agent Session

- 变更：新增 `SessionRuntime` 与 `SessionStore` seam，维护单个 active session 的版本化快照；插件加载时恢复历史，每轮模型返回后保存完整消息，新建会话时生成新 ID 并清空历史。
- 存储：新增 `PluginDataStore` adapter，在旧版扁平 settings 数据顶层保留 `activeSession`，设置与会话独立更新且通过队列串行写入，损坏或不支持版本的会话快照会被忽略。
- 交互：侧栏重新打开时显示已恢复的会话，并增加“新建助手会话”命令；待确认 `ChangePlan` 含运行时执行闭包，本轮明确不持久化。
- 验证范围：Vitest 只发现 `tests/**/*.test.ts`，ESLint 也忽略只读参考目录 `kimi-code-main/`，标准验证不再分析该独立项目。
- 验证：10 个测试文件、41 项测试通过；`npm.cmd run build`、`npm.cmd run lint` 和 `git diff --check` 通过。

## 2026-08-21：确认写回前展示真实行级 diff

- 选择依据：按当前“下一步”清单选投入产出最高的一项。写回确认是每次编辑都会经过的信任界面，原来只显示整篇建议正文；diff 是纯逻辑模块，可单元测试、无外部依赖，并为后续逐个 hunk 接受变更打基础。LinkContext 与双链需要先定候选打分和消歧策略，成本更高，排在其后。
- 变更：新增 `src/changes/text-diff.ts`（公共前后缀裁剪 + LCS 行对齐 + hunk 分组 + `@@` 位置 + 截断标记）和 `src/ui/diff-view.ts` 共享渲染 seam；侧栏待确认卡片与整理预览弹窗改为显示带上下文的新增/删除行，整理弹窗把完整结果收进可展开区域；`styles.css` 增加 diff 样式并删除不再使用的双栏预览样式。
- 边界：diff 只用于展示，写回仍以 `ChangePlan` 的 `TextChange` 和源版本校验为准；展示层按 `\r?\n` 归一化行尾，不影响写回内容；对齐矩阵超过 100 万格时退化为整块替换，渲染超过 400 行时截断并提示。
- 验证：11 个测试文件、48 项测试通过；`npm.cmd run build`、`npm.cmd run lint` 和 `git diff --check` 通过。Obsidian 内的视觉效果尚未人工确认。
- 后续：逐个 hunk 接受/拒绝与选区替换，再进入 LinkContext 候选筛选与双链写回。

## 2026-08-21：按 Kimi Code 借鉴清单收敛上下文成本

- 选择依据：先解决每轮固定开销和单条工具结果没有上限的问题。原来 `readNote` 与 `listNotes` 返回全量、技能正文全部进系统提示、运行环境提示插在系统提示之后导致前缀每轮失效、轮数用尽直接抛异常；这些都不涉及写回信任边界，改动局部且可单元测试。详细取舍见[Kimi Code 借鉴清单](../engineering/kimi-code-借鉴清单.md)。
- 变更：新增 `src/agent/tool-result-budget.ts`（单条结果 20000 字符上限、保留前 6000 字符并说明取回方式、避免切断代理对）；`readNote` 改为行窗口分页并返回 `hasMore`/`nextOffset`，`listNotes` 上限 100 篇并返回 `total`/`returned`/`hasMore`；`skills.ts` 改为清单式渐进披露并新增 `useSkill` 只读工具，支持 `when-to-use` 与 `disable-model-invocation`；`AgentLoop` 把运行环境提示改为追加在当前用户消息之前、同轮等价调用只执行一次、跨轮连续重复升级提示、连续 6 次或到达轮数上限时注入收尾提示并为悬空工具调用补齐结果；`main.ts` 装配 `createSkillTools` 并补 `useSkill` 过程文案。
- 边界：行窗口按原始行尾逐字切片，保证窗口内容仍能作为 `editNote` 的精确匹配文本；收尾轮仍必须发送工具定义，因为 OpenAI-compatible 端点拒绝空 `tools`；预算与分页阈值先写成常量，未做成设置项；不做澄清提问工具、计划模式、TODO、按 token 触发压缩与模型生成摘要。
- 验证：12 个测试文件、68 项测试通过；`npm.cmd run build`、`npm.cmd run lint` 和 `git diff --check` 通过。技能清单与截断提示对模型实际行为的影响尚未在 Obsidian 中人工确认。
- 后续：观察真实对话后再决定是否引入按 token 估算触发压缩与模型生成摘要；产品侧仍回到逐个 hunk 接受变更与 LinkContext 双链。
