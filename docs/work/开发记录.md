## 2026-08-22：整理选区并支持替换选区写回

- 选择依据：按[实现状态](../engineering/实现状态.md)“下一步”第 2 项里更有产品价值的一半。整理整篇笔记时用户没法只处理手上这一段，而[开发共识](../engineering/开发共识.md)早就约定「可选替换选区」；选区定位和写回方式构建都是纯函数，可以先 TDD 再接 UI。字符级行内 diff 只是展示精度，排在其后。
- 变更：新增 `src/changes/selection-target.ts`（`locateSelection`：偏移命中优先、退回唯一文本匹配、LF/CRLF 两种行尾都试）和 `src/changes/organize-write.ts`（`buildOrganizeWriteChoices`：有选区时「替换选区」在前、「追加到笔记末尾」在后，两者共用同一个源版本）；`ObsidianVaultAdapter.getActiveSelection` 从 `MarkdownView.editor` 取选区文本和起始偏移；`NoteAssistant.organize` 增加 `selectionOnly`，提示词说明这只是一段选区、缺少的上下文写成待澄清问题；`ChangePreviewModal` 改为可切换写回方式并同步重画 diff，「复制结果」改为「复制整理结果」复制整理结果本身；`confirmRemoteSend` 增加范围文案；`runOrganize` 接入选区并把发送范围确认改为按范围记忆；`styles.css` 补写回方式样式。
- 信任边界：编辑器可能有未保存改动，而写回以 `vault.read` 的内容为基准，所以选区必须在已保存正文里重新定位；文本重复且偏移失效、或正文里根本找不到时一律拒绝定位，退回整篇整理并在过程与通知里说明原因，绝不按猜测的偏移写回。两种写回方式都只是 `ChangePreview`，`expectedRevision` 相同，落盘仍由 `ObsidianVaultAdapter.update` 做内容哈希校验。发送范围确认改为记住范围：确认过全文后更窄的选区不再重复确认，只确认过选区时改发全文会重新弹窗，避免范围被静默放大。
- 边界：只有固定「整理」动作支持选区，Agent 对话、`updateNote`/`editNote` 和「寻找关联」仍以整篇笔记为单位；整理预览仍不提供逐处勾选（追加与替换都是单处变更）；替换选区会删掉选中的原文，属于用户显式选择，默认写回方式仍是追加。
- 验证：20 个测试文件、140 项测试通过（新增 `selection-target` 9 项、`organize-write` 8 项、`note-assistant-organize` 2 项）；`npm.cmd run build`、`npm.cmd run lint` 和 `git diff --check` 通过。Obsidian 内的写回方式切换与替换选区结果尚未人工确认。
