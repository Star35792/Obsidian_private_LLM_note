## TASK-20260822-04：模型请求重试

- 状态：`done`
- 目标：网络中断、服务限流或 5xx 时自动重发同一请求，重试次数可配置，并让用户看见重试原因与等待时间。
- 范围内：新增纯逻辑模块 `src/model/model-retry.ts`（失败分类、指数退避、`Retry-After`、次数校验、重试执行器）；`OpenAiCompatibleAdapter` 的 `complete` 与 `completeAgent` 接入重试并把非 2xx 转成 `ModelHttpError`；`settings.modelRetryCount` 与 0–5 的设置项；`AssistantView.resetStream`；`main.ts` 把重试写进侧栏处理过程；`tests/model-retry.test.ts`。
- 范围外：不做请求级超时（等服务端返回或连接失败）；不做熔断与全局失败计数；不重试写回与 Vault 操作（写回只由用户确认触发）；不改动确认边界、diff 展示与 Agent Loop 轮次逻辑；不在流式中途断线时逐段续传（重发整个请求）。
- 验收：
  - 网络失败（`Failed to fetch`、`net::`、`ECONN*`）、408/409/425/429、5xx 和空流会重试；取消、401/400 之类的 4xx 和「尚未配置 API key」不重试。
  - 等待时间按 800ms×2^n 增长并封顶 8 秒；服务端 `Retry-After` 更长时按它等待，最多 20 秒；非法或非正数 `Retry-After` 按未提供处理。
  - `modelRetryCount` 为 0 时只请求一次；超出 0–5 或非整数的旧数据在使用前回退到默认值 2。
  - 重试前若已经显示过增量，侧栏先清空流式输出再接收，不会把两次输出拼在一起。
  - 重试在侧栏处理过程里显示原因、等待时间和第几次尝试。
  - 取消（`AbortSignal`）会中断等待，不再发起后续尝试。
  - 测试、`npm.cmd run build`、`npm.cmd run lint` 和 `git diff --check` 通过。
- 假设：同一请求重发是安全的，因为模型请求没有副作用；`requestUrl` 抛出的错误不带状态码，所以改用 `throw: false` 自己按状态码分类。
- 风险：对不该重试的错误重试会放大费用与等待，所以默认只重试连接层与明确可恢复的状态码；流式中途断开后重发会重新生成，因此必须先让界面丢弃已显示增量。
- 依赖：现有 `ModelPort`/`AgentModelPort`、`OpenAiCompatibleAdapter`、`AssistantView` 处理过程展示。
- 计划：先写分类、退避与执行器的单元测试和纯函数 → 适配器接入并统一 HTTP 错误 → 设置项与默认值 → 侧栏重试提示 → 运行验证并同步文档。
