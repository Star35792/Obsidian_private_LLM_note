# Note_Edit 文档入口

这是项目文档的默认入口。每次 AI 开发任务都从本页开始，再按任务范围向树的分支和叶子渐进展开；不要一开始加载整个文档库。

## 默认阅读路径

1. [项目术语表](../CONTEXT.md)：先确认术语、核心不变量和禁用旧称。
2. [当前计划](work/当前计划.md)：确认本周期目标、进行中的工作和完成清单。
3. [开发流水线](process/ai-development-pipeline.md)：遵循阅读、澄清、开发、验证、memory 和提交顺序。
4. [权限与确认规范](process/权限与确认规范.md)：判断当前动作是否可以自动执行，或必须停下来确认。
5. [开发记录](work/开发记录.md)：了解最近什么时候做了什么，以及对应的验证和提交。
6. 根据任务进入一个分支，按需读取叶子文档。

## AI 启动协议

每次新任务必须先完成下面四件事，再读取大量专题或修改代码：

1. 在 [当前计划](work/当前计划.md) 创建或认领一个唯一任务卡，状态设为 `in_progress`。
2. 写出“目标、范围外、验收标准、当前假设、风险和下一步工具动作”六项摘要。
3. 根据任务选择一条分支，读取最少的相关叶子，并记录已读取路径。
4. 在没有任务卡、验收标准或权限判断时，不开始代码修改。

任务完成必须留下三个结果：任务卡完成清单、验证命令/手动验收结果、[开发记录](work/开发记录.md) 的日期条目。只有这三个结果齐全，任务才能从 `in_progress` 变为 `done`。

## 分支选择

| 当前任务 | 先读 | 继续读取 |
| --- | --- | --- |
| 产品范围或验收 | `product/规格说明.md` | 相关交互、领域专题 |
| UI、模块或 Obsidian 接口 | `engineering/插件设计.md` | 实现约束、文件工具、实现状态 |
| AI 开发过程、权限或提交 | `process/ai-development-pipeline.md` | 权限规范、当前计划、开发记录 |
| 已有决策或方案取舍 | `adr/` | 与主题对应的产品/工程叶子 |
| 恢复上次工作 | `work/当前计划.md` | `work/开发记录.md`、相关 memory |
| 稳定跨会话约定 | `memory/MEMORY.md` | 被索引的主题记忆 |

## 渐进式披露规则

- 根入口只保留导航、优先级和树，不复制专题正文。
- 分支 README 只说明本分支边界和叶子用途；专题细节只写在叶子中。
- 叶子之间通过相对链接引用，不通过重复粘贴同步内容。
- 新术语先进入 `CONTEXT.md`；真实取舍进入 `adr/`；当前进度进入 `work/`；跨会话规律进入 `memory/`。
- 文档变多时优先增加分支 README 和索引，不把所有内容重新堆回根入口。
- 一个任务只允许一个活动任务卡；并行工作必须拆成明确的子卡，并标注依赖关系。

## 冲突与更新规则

用户当前指令 > `CONTEXT.md` > ADR > 产品/工程专题 > process 规范 > memory 中的历史经验。发现代码与文档不一致时，以代码和测试事实为证据，修正文档或记录未决事项；不要静默选择一方。

每次开发结束至少更新：`work/当前计划.md` 的状态、`work/开发记录.md` 的时间记录，以及确实具有跨会话价值的 `memory` 主题。完成后才允许把对应任务标记为 done。
