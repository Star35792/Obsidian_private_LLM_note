# AI 开发流水线

本文是 Note_Edit 项目的默认 AI 开发流程。它把一次需求从阅读上下文推进到代码、验证、记忆和 Git 提交，作为项目内可复用的工作协议。

## 总原则

- 用户当前指令优先于项目文档；项目文档之间以 `CONTEXT.md`、ADR、专题文档、动态状态的顺序解释冲突。
- 先读再改：先读取相关文档、代码和测试，再决定修改范围。
- 一次只推进一个可验证的主要目标，避免把尚未确认的需求直接扩展成大重构。
- 本地、可逆的编辑和测试可以直接执行；删除、覆盖未提交工作、推送和影响共享系统的操作必须重新确认。
- 输出先给结果和阻塞点，不给时间预估，不展示隐藏思维链。

## 阶段与产物

### 1. 阅读上下文

目标是建立当前任务的事实边界，而不是立即提出方案。

阅读顺序：

1. `CONTEXT.md`：术语、核心不变量和避免使用的旧称。
2. `docs/adr/`：已经做出的架构决策及其取舍。
3. `docs/` 下与任务相关的专题文档和 `docs/memory/`：稳定约束、当前状态和用户协作偏好。
4. 相关源码、测试、配置和 `git status`：确认文档与代码是否一致。

产物是简短的事实清单：当前实现、目标行为、明确限制、冲突点和待确认事项。

### 2. 需求澄清

把用户请求转换为可验收的需求，不把猜测写成事实。

必须明确：

- 用户要改变的行为，以及明确不改变的行为；
- 输入范围、输出形式、权限和确认边界；
- 验收场景和失败时的预期；
- 影响多个方案的未决选择。

如果缺少的信息不会改变实现路径，记录合理假设并继续；如果会改变范围、数据安全或架构，先向用户提问。澄清结果需要回写到任务记录或 ADR，而不是只留在对话中。

### 3. 方案与切片

先找到现有相似实现，选择与当前架构一致的最小切片。方案应列出：

- 要修改的模块及其接口边界；
- 不需要修改的模块；
- 测试策略和端到端验收路径；
- 是否需要新增术语、ADR、配置或文件。

只有出现真实的不可逆取舍、未来读者难以理解且存在替代方案时才新增 ADR。不要为了“以后可能需要”创建抽象或文件。

### 4. 代码开发

- 修改前必须读取目标文件和调用方；修改已有文件优先于新建文件。
- 先写能表达需求的测试，再实现最小行为；修复发现的类型、安全和边界问题。
- 系统边界校验用户输入、外部 API、Vault 路径和模型输出；内部不可能发生的场景不添加无意义兜底。
- 保持 Note_Edit 的核心不变量：模型只能发起写工具调用，写入必须经过 `ChangePlan` 和用户确认。
- 变更保持局部，不顺手重构无关代码，不添加未经请求的兼容层。

### 5. 测试与验证

按风险选择验证范围，至少执行与改动相关的：

1. 单元测试：纯逻辑、解析器、边界和错误路径。
2. 集成测试：模块之间的接口、模型协议和 Vault Adapter。
3. 构建与 lint：`npm.cmd run build`、`npm.cmd run lint`。
4. 端到端或手动验收：按需求中的用户场景检查 UI、确认边界和实际写回。

失败时记录根因并调整方法，不重复无变化地重试同一命令。测试通过后检查 `git diff --check` 和工作区状态。

### 6. 更新项目 memory

只把跨会话仍然有价值的内容写入 `docs/memory/`：

- 已验证的架构约束和实现模式；
- 用户稳定的协作偏好；
- 当前阶段的完成项、已知限制和下一步；
- 容易重复犯错的边界规则。

不要写临时聊天上下文、未经验证的推测、重复的 `CONTEXT.md` 内容或完整测试日志。新增主题文件后，必须在 `docs/memory/MEMORY.md` 添加索引；更新时保持已有标题和 frontmatter 结构。

### 7. Git 提交

提交前并行检查 `git status`、`git diff`、`git log`，确认：

- 变更文件属于本次任务，没有把用户未授权的无关文件带入提交；
- 没有 API key、凭据或生成物；
- 测试、构建和 lint 状态已记录；
- 提交信息使用 Conventional Commits，说明行为变化和目的。

然后只暂存明确属于本次任务的文件，创建新的提交，不修改 Git 配置、不跳过 hooks、不 amend 已有提交。提交后再次运行 `git status`，把提交哈希和验证结果反馈给用户。

## 完成门槛

一次 AI 开发任务只有同时满足以下条件才算完成：

- 需求边界和验收标准已明确；
- 代码与测试已实现，相关验证通过；
- 稳定决策和跨会话经验已写入仓库文档或 memory；
- Git 提交只包含授权范围内的变更，工作区状态已说明。
