# 文件工具

## 1. 目标

文件工具让 AI 能够在用户授权的范围内理解和整理 Vault，而不是把 AI 变成一个拥有任意文件权限的脚本执行器。

所有路径都相对于当前 Obsidian Vault。工具只处理 Markdown 笔记和用户明确允许的笔记资源，不访问 Vault 之外的文件。

## 2. 工具清单

### 只读工具

| 工具 | 作用 | 关键参数 |
| --- | --- | --- |
| `listNotes` | 列出笔记或文件夹下的笔记 | `scope`、`limit` |
| `searchNotes` | 按标题、内容或标签搜索 | `query`、`scope`、`limit` |
| `readNote` | 读取单篇笔记 | `path` |
| `getLinkContext` | 获取出链、反向链接和相关候选 | `path`、`depth` |

只读工具可以自动调用，但仍需要限制范围、数量和返回内容大小。默认不读取整个 Vault。

### 变更工具

| 工具 | 作用 | 默认策略 |
| --- | --- | --- |
| `createFolder` | 新建文件夹 | 预览后确认 |
| `createNote` | 新建 Markdown 笔记 | 预览后确认，禁止覆盖同名文件 |
| `updateNote` | 对已有笔记做最小差异修改 | 预览后确认，检查版本 |
| `moveNote` | 移动或重命名笔记 | 预览后确认，检查目标冲突 |
| `trashNote` | 移入 Obsidian trash | 默认关闭，二次确认 |

工具本身不暴露“永久删除”。归档和删除在界面上使用明确的“移入 trash”文案，避免让用户误以为内容仍在原位置。

## 3. 统一调用流程

```text
用户目标
  -> AI 调用只读工具收集最小上下文
  -> AI 生成 FileOperation[]
  -> VaultToolset.plan()
  -> 本地路径、版本、冲突和双链影响检查
  -> 展示 ChangePlan 预览
  -> 用户逐项确认
  -> VaultToolset.apply()
  -> 返回每项结果和失败原因
```

AI 永远不能直接调用 `createFolder`、`createNote`、`updateNote`、`moveNote` 或 `trashNote`。这些名称代表内部 Adapter 能力，外部只暴露 `plan` 和确认后的 `apply`。

## 4. 文件操作模型

```ts
type FileOperation =
  | { kind: 'create-folder'; path: VaultPath }
  | { kind: 'create-note'; path: VaultPath; content: string }
  | { kind: 'update-note'; path: VaultPath; changes: TextChange[]; expectedRevision: string }
  | { kind: 'move-note'; from: VaultPath; to: VaultPath }
  | { kind: 'trash-note'; path: VaultPath };

type ChangePlan = {
  id: string;
  changes: Array<{
    id: string;
    operation: FileOperation;
    reason: string;
    diff?: string;
    linkImpact: string[];
    requiresConfirmation: boolean;
  }>;
  expiresAt: number;
};
```

`ChangePlan` 是一次性的预览对象。源文件版本、目标路径或用户选择发生变化后，旧计划失效，必须重新生成。

## 5. 安全规则

- 只接受 Vault 相对路径；拒绝绝对路径、`..` 和符号链接逃逸。
- 新建文件夹和笔记前检查同名目标，不静默覆盖。
- 修改使用最小文本差异，并校验生成计划时的版本号。
- 移动或重命名使用 Obsidian 原生 `FileManager`，不手动重写所有双链。
- 归档使用可恢复的 Obsidian trash；默认不提供批量归档。
- 多项操作按“创建文件夹、创建笔记、修改、移动、归档”的顺序执行，任一项失败就停止后续操作并报告结果。
- 取消、过期或拒绝计划时，不发生任何文件变化。
- 文件内容和路径只发送给外部模型的必要部分；模型不获得文件工具权限。

## 6. 与双链的关系

- 新建笔记时，AI 可以建议初始双链，但必须和笔记内容一起预览。
- 修改笔记时，重复链接、歧义链接和未解析链接都要在预览中标记。
- 移动或重命名交给 Obsidian 原生链接更新机制，反向链接由 MetadataCache 重新派生。
- 归档被链接的笔记时，先展示受影响的来源；不自动删除来源中的链接。

## 7. 首版实现顺序

1. `listNotes`、`searchNotes`、`readNote` 和 `getLinkContext`。
2. `ChangePlan`、路径校验、版本校验和变更预览。
3. `createFolder`、`createNote` 和 `updateNote`。
4. 使用 `FileManager` 实现 `moveNote`。
5. 最后实现默认关闭的 `trashNote`，补充二次确认和恢复测试。

## 8. 验收场景

- AI 根据用户要求创建笔记时，先展示路径、内容和初始双链，用户取消后不创建任何文件。
- 用户要求整理现有笔记时，工具只修改预览显示的范围。
- 同名笔记存在时，新建操作被拒绝并要求选择路径。
- 源文件在预览后被用户编辑时，应用计划失败并要求重新生成。
- 移动笔记后，Obsidian 的正向链接和反向链接仍然可用。
- 归档操作进入可恢复 trash，且不会静默删除引用它的链接。
