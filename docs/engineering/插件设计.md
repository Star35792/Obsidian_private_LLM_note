# 插件设计

## 1. 首版体验

插件提供一个右侧边栏“思维整理”。用户在当前笔记中记录内容后，在边栏输入框里用 `/` 唤醒命令与技能（整理、澄清、挑战、行动化、寻找关联，以及 `skills/` 下的用户技能），用 `@` 指定本轮要读或要改的笔记与文件夹；整理结果同时提供分类建议。

边栏由上到下分为：

1. 上下文：当前选区、当前笔记，以及用户用 `@` 指定的笔记与文件夹（只声明范围，正文按需读取）。
2. 对话与输入框：`/` 唤醒命令与技能候选，`@` 唤醒笔记与文件夹候选；不再有互斥的动作按钮，“挑战”仍进入逐轮会话，“寻找关联”仍专门生成双链建议。
3. 结果：结构化草稿、分类建议、待澄清问题、挑战问题或关联建议。
4. 预览：展示将要写回的最小差异。
5. 操作：逐条接受、全部接受、复制或取消。

AI 处理期间不锁定编辑器。源笔记变化后，旧预览自动失效，用户需要重新生成。

## 2. 核心 Module

以下名称中的 Module、Interface、Seam 和 Adapter 使用工程设计含义，不等同于 TypeScript 关键字。

### NoteAssistant Module

它是插件功能的外部 Interface，隐藏上下文收集、候选筛选、模型调用、结果校验和变更规划。

```ts
interface NoteAssistant {
  propose(request: AssistantRequest): Promise<AssistantProposal>;
}
```

调用者只提供动作、来源范围和用户补充要求，得到一个不可直接写回的 Proposal。界面不需要知道提示词、模型响应格式或双链排名算法。

### ChallengeSession Module

它管理一轮思维挑战的状态，隐藏问题选择、回答记录、强度限制和结束摘要。

```ts
interface ChallengeSession {
  start(source: NoteSource, intensity: ChallengeIntensity): Promise<ChallengeTurn>;
  answer(sessionId: string, answer: string): Promise<ChallengeTurn | ChallengeSummary>;
  stop(sessionId: string): Promise<ChallengeSummary>;
}
```

`ChallengeSession` 只返回下一问或摘要，不直接修改笔记。它可以通过内存 Model Adapter 测试，结束后的摘要再交给 ChangePlan 生成预览。

### ChangePlan Module

它负责把 Proposal 转成可预览、可校验和可提交的文件变更。

```ts
interface ChangePlan {
  preview(proposal: AssistantProposal): Promise<ChangePreview>;
  commit(preview: ChangePreview, acceptedChangeIds: string[]): Promise<CommitResult>;
}
```

该 Module 内部处理源文件版本校验、最小文本替换、链接去重和失败回滚。界面只操作变更 ID。

### LinkContext Module

它负责从 Obsidian 的本地元数据中找到少量候选，并把原生链接解析成统一领域对象。

```ts
interface LinkContext {
  collect(source: NoteSource, limit: number): Promise<LinkCandidate[]>;
}
```

标题、别名、路径消歧、已有出链、反向链接和候选排序都隐藏在实现中。该 Module 不调用远程模型。

### VaultToolset Module

它是 AI 与 Obsidian Vault 之间唯一的文件工具 Interface，隐藏路径校验、版本检查、差异计算和原生文件操作。

```ts
interface VaultToolset {
  inspect(request: InspectRequest): Promise<InspectResult>;
  plan(operations: FileOperation[]): Promise<ChangePlan>;
  apply(planId: string, acceptedChangeIds: string[]): Promise<ApplyResult>;
}
```

`inspect` 覆盖列出、搜索、读取和双链上下文；`plan` 覆盖新建文件夹、新建笔记、修改、移动和归档；`apply` 只接受已经展示给用户并确认的变更 ID。AI、Model Adapter 和界面都不能直接访问 Obsidian Vault。

## 3. Seam 与 Adapter

### 模型 Seam

外部模型是不可控依赖，通过小型 Interface 注入：

```ts
interface ModelPort {
  complete(request: ModelRequest, options?: ModelCompletionOptions): Promise<ModelResponse>;
}

interface ModelCompletionOptions {
  signal?: AbortSignal;
  onDelta?: (delta: string) => void;
}

interface ModelResponse {
  content: string;
  streamed: boolean;
}
```

- 生产环境使用 OpenAI-compatible Adapter。
- Adapter 接受用户填写的完整端点，并按设置选择 Chat Completions 或 Responses API，不修改 URL。
- `onDelta` 只传递可见的输出增量，用于展示结构化草稿；不承载隐藏思维链。
- 流式能力不可用时可回退普通响应，并通过 `streamed` 告知调用方。
- 连接层失败（网络错误、限流、5xx、空流）由 Adapter 按可配置次数重发同一请求，并把原因、等待时间和尝试序号回调给界面；取消和明确的请求错误立即抛出。重试策略本身放在不依赖 Obsidian 与 `fetch` 的纯模块里。
- 测试使用固定响应的内存 Adapter。
- 将来接入本地模型时复用同一 Seam，不改变 NoteAssistant 的 Interface。

### 笔记库 Seam

文件读取、MetadataCache 查询和写入通过 `VaultPort` 进入：

```ts
interface VaultPort {
  list(scope: VaultScope): Promise<NoteRef[]>;
  search(query: string, scope: VaultScope): Promise<SearchResult[]>;
  read(ref: NoteRef): Promise<NoteSnapshot>;
  resolveLink(sourcePath: string, linktext: string): Promise<NoteRef | null>;
  createFolder(path: VaultPath): Promise<void>;
  createNote(path: VaultPath, content: string): Promise<NoteSnapshot>;
  updateNote(ref: NoteRef, changes: TextChange[], expectedRevision: string): Promise<NoteSnapshot>;
  moveNote(ref: NoteRef, target: VaultPath): Promise<NoteSnapshot>;
  trashNote(ref: NoteRef): Promise<void>;
}
```

- 生产环境使用 Obsidian Vault Adapter。
- 测试使用内存 Vault Adapter。
- Interface 保证提交时检查版本，避免覆盖用户刚刚输入的内容。
- `moveNote` 使用 Obsidian 原生 `FileManager`，让正向链接和反向链接按 Obsidian 规则更新。
- `trashNote` 使用可恢复的 trash，不提供不可逆删除。

## 4. 数据流

```text
AssistantView
  -> 展示读取与发送确认阶段
  -> NoteAssistant.propose()
  -> LinkContext.collect()       本地候选
      -> ModelPort.complete()    远程或本地模型，按增量更新草稿
      -> ProposalValidator           纯计算校验
  -> ChangePlan.preview()
  -> 用户选择变更
  -> VaultToolset.plan()
  -> 用户确认文件操作计划
  -> VaultToolset.apply()
      -> VaultPort 变更方法
```

界面不会直接访问模型或修改文件；模型也不会直接得到 Vault Interface。这使隐私过滤、预览和写回规则集中在 NoteAssistant 与 ChangePlan 内部。

## 6. 首版命令

| 命令 ID | 显示名称 | 输入范围 |
| --- | --- | --- |
| `capture-thought` | 捕捉当前想法 | 当前选区优先，否则打开快速输入 |
| `organize-current-note` | 整理当前笔记 | 当前选区优先，否则当前笔记 |
| `clarify-current-note` | 澄清当前想法 | 当前选区优先，否则当前笔记 |
| `challenge-current-thought` | 挑战当前想法 | 当前选区优先，否则进入挑战会话 |
| `actionize-current-note` | 生成下一步 | 当前选区优先，否则当前笔记 |
| `suggest-related-notes` | 寻找相关笔记 | 当前笔记和本地候选 |

命令 ID 发布后保持稳定。命令会打开边栏并直接运行对应流水线；同一批动作在边栏里用 `/名称` 触发。

## 7. 开发顺序

1. 建立插件骨架、设置和右侧视图。
2. 完成内存 Vault Adapter、领域类型和 ChangePlan 测试。
3. 接入 Obsidian Vault Adapter，实现预览与安全写回。
4. 实现本地 LinkContext 和双链消歧，不接入 AI 也能验证链接行为。
5. 接入模型 Adapter，完成整理、分类建议和关系判断。
6. 实现 ChallengeSession，先用固定问题和内存 Adapter 验证状态流。
7. 实现 VaultToolset 的只读工具和 ChangePlan 预览。
8. 接入新建、修改、移动和可恢复归档，并按确认边界逐项开放。
9. 按规格中的验收场景进行手动测试。

先保证双链与写回正确，再增加模型能力。模型输出始终只是 Proposal，不拥有写文件权限。
