# 实现状态

最后同步：2026-08-18

本页只记录代码现状和近期开发顺序。产品目标和长期约束仍以[规格说明](../product/规格说明.md)及其他专题文档为准。

## 已实现

- Obsidian 插件骨架、中文右侧边栏、设置页和六个稳定命令 ID。
- “整理当前笔记”完整主链路：读取当前笔记、会话首次外发确认、调用模型、校验 Proposal、渲染 Markdown、预览并安全写回。
- JSON Proposal 校验，包含概括、已确认内容、待澄清问题、未验证假设、下一步、分类建议和整理依据。
- 内容哈希版本校验；预览生成后源笔记发生变化时拒绝覆盖。
- 默认保留原文并把整理结果追加到笔记末尾，同时支持复制结果。
- OpenAI-compatible 模型接入，支持 Chat Completions 和 Responses API 两种请求及响应格式。
- API 地址按用户填写的完整端点原样请求，不自动补全或拼接路径。
- SSE 流式生成：界面展示读取、确认、请求、接收、校验和预览阶段，并实时显示结构化草稿。
- 流式连接不可用时回退到普通响应，并在界面中明确显示回退结果。
- 整理结果展示可回指原文的“整理依据”，不请求、不展示也不伪造模型隐藏思维链。

## 部分实现

- `ChangePlan`、内存变更逻辑和 Obsidian Vault Adapter 已接通当前笔记的追加写回；新建、移动和归档等文件操作尚未接入。
- 预览已同时展示原文和整理结果，但还不是逐字符或逐行的新增/删除文本 diff。
- 命令和边栏已经提供六种动作入口，目前只有“整理”执行真实处理，其余动作会显示“后续支持”。
- 模型取消信号已保留在接口中，界面尚未提供主动取消按钮。

## 未实现

- 捕捉、澄清、挑战、行动化的模型流程和各自的 Proposal 契约。
- `LinkContext` 本地候选筛选、同名消歧、已有链接去重和双链建议。
- 逐条确认双链并用原生 Wiki Link 写回。
- 选区替换、真正的文本 diff 和逐项接受变更。
- `VaultToolset` 的新建文件夹、新建笔记、移动和可恢复归档。

## 当前兼容性边界

- 设置中的格式必须与完整 API 端点匹配。Chat Completions 请求不能发送到 Responses 端点，反之亦然。
- Responses API 是否可用取决于模型供应商是否实现该端点和相应事件格式。
- SSE 使用运行环境的原生 `fetch`；仅在流式能力不可用时回退 Obsidian `requestUrl` 普通请求。
- 当前整理范围是打开的整篇 Markdown 笔记，尚未优先处理编辑器选区。
