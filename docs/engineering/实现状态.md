# 实现状态

最后同步：2026-08-21

本页只记录代码现状和近期开发顺序。产品目标和长期约束仍以[规格说明](../product/规格说明.md)及其他专题文档为准。

## 已实现

- Obsidian 插件骨架、中文右侧边栏、设置页和六个稳定命令 ID。
- “整理当前笔记”完整主链路：读取当前笔记、会话首次外发确认、调用模型、校验 Proposal、渲染 Markdown、预览并安全写回。
- JSON Proposal 校验，包含概括、已确认内容、待澄清问题、未验证假设、下一步、分类建议和整理依据。
- 内容哈希版本校验；预览生成后源笔记发生变化时拒绝覆盖。
- 默认保留原文并把整理结果追加到笔记末尾，同时支持复制结果。
- OpenAI-compatible 模型接入，支持 Chat Completions 和 Responses API 两种请求及响应格式。
- API 地址按用户填写的完整端点原样请求，不自动补全或拼接路径。
- SSE 流式生成：界面展示读取、确认、请求、接收、校验和预览阶段，并实时显示结构化草稿。
- 流式连接不可用时回退到普通响应，并在界面中明确显示回退结果。
- 整理结果展示可回指原文的“整理依据”，不请求、不展示也不伪造模型隐藏思维链。
- Agent Loop 已接入侧栏自然语言对话，保留多轮消息和工具结果上下文。
- Agent 对话首轮只发送用户请求和活动笔记路径，不再自动读取或拼接笔记正文；运行时路径提示不会沉淀进会话历史。
- `searchNotes` 返回每篇笔记最多 3 个有界命中片段；模型仅在确需全文理解或编辑时调用 `readNote`，工具调用会显示在处理过程。
- `readNote` 按行窗口分页（默认前 400 行、单窗口 12000 字符），返回 `startLine`、`endLine`、`totalLines`、`hasMore` 和 `nextOffset`；窗口内容按原始行尾逐字截取，可直接作为 `editNote` 的 `old_string`。
- `listNotes` 最多返回 100 篇并报告 `total`、`returned` 和 `hasMore`。
- 单条工具结果超过 20000 字符时截断到前 6000 字符，并在结果里说明如何分段或缩小范围取回其余内容。
- `skills/` 下的 Markdown 笔记会在每轮对话前加载为可编辑技能指令；系统提示只列出名称、说明和“何时使用”，正文由模型按需通过 `useSkill` 读取，`disable-model-invocation: true` 的技能不进入清单。
- 运行环境提示（活动笔记路径）追加在历史之后、当前用户消息之前，保持系统提示前缀稳定以复用供应商侧的 prompt 缓存，且不沉淀进会话历史。
- 同一轮内参数等价的工具调用只执行一次并复用结果；跨轮连续重复调用会收到升级提示，连续 6 次后本轮不再执行工具。
- 达到工具调用轮数上限时注入收尾提示并直接给出结论，同时为悬空的工具调用补齐结果，保证保存的历史仍然合法。
- 只读 Vault 工具可自动调用；`updateNote` 只生成带源版本校验的 `ChangePlan`，侧栏确认卡片确认后才写回。
- 待确认变更和整理预览都展示行级 diff：公共前后缀裁剪加 LCS 对齐，按 `@@` 位置分组成带上下文的 hunk，超大差异退化为整块替换并标注截断。
- `LinkContext` 本地候选收集：未加链接的原文提及、反向链接、共享标签和（`depth` 为 2 时）二跳共同邻居四类信号打分排序，源笔记已链接的目标（含未解析同名链接）不进入候选，同名候选标注 `ambiguous` 并给出全部路径与按路径的链接文本，数量受设置项 `localCandidateLimit` 限制并报告 `hasMore`。整个过程只用 Obsidian 本地元数据，不外发 Vault 内容。
- “寻找关联”完整主链路：本地候选 → 有界候选片段 → 模型判断关系 → 逐条确认 → 原生 Wiki Link 写回。
- 候选片段（`LinkBrief`）去掉 frontmatter、折叠空行、按行或句边界截断到 400 字符并标注 `truncated`，数量受 `modelCandidateLimit` 限制；发送范围弹窗逐篇列出路径和片段字符数。
- `LinkSuggestion` 契约由插件校验：目标必须来自候选列表，关系类型限定六种，只展示 high/medium 置信度，`low` 会被拒绝并说明原因。
- 双链插入位置由锚点句子定位：模型给出逐字来自原文且全文唯一的锚点句子，不给行号或偏移；锚点缺失、重复、与前一条建议重叠，或同一目标重复建议都会被逐条拒绝并给出中文原因。
- 只允许加链接：把改写句子里的 Wiki Link 还原成显示文本后必须以锚点句子开头，等于锚点句子记为“只加链接”，更长记为“追加一句说明”，其他情况一律拒绝，模型无法借写链接改写原文。
- 同名候选必须使用完整路径链接，否则该条建议被拒绝，保证消歧结果不被模型忽略。
- 每条双链建议独立写回：接受时重新读取笔记、重新定位锚点、经内容哈希校验后只替换该句；单条失败只在该卡片显示原因，不影响其他建议。

## 部分实现

- `ChangePlan`、内存变更逻辑和 Obsidian Vault Adapter 已接通当前笔记的追加写回；新建、移动和归档等文件操作尚未接入。
- 预览已展示带上下文的行级新增/删除差异，但还没有字符级行内 diff，也不能逐个 hunk 接受或拒绝。
- 命令和边栏提供六种动作入口；“整理”和“寻找关联”已接通完整链路，自然语言对话已可执行通用 Agent Loop，其余四种动作和固定动作的专用 Skill 尚未迁移。
- 双链只写正向链接（Obsidian 自动派生反链），只支持整句锚点；块引用、标题锚和为未解析链接新建笔记尚未实现。
- 上下文成本已有单条结果预算、分页和技能渐进披露；历史压缩仍按消息条数触发，尚未按 token 估算触发，也不调用模型生成摘要（见[Kimi Code 借鉴清单](kimi-code-借鉴清单.md)待评估段）。
- 模型取消信号已保留在接口中，界面尚未提供主动取消按钮。

## 当前兼容性边界

- 设置中的格式必须与完整 API 端点匹配。Chat Completions 请求不能发送到 Responses 端点，反之亦然。
- Responses API 是否可用取决于模型供应商是否实现该端点和相应事件格式。
- SSE 使用运行环境的原生 `fetch`；仅在流式能力不可用时回退 Obsidian `requestUrl` 普通请求。
- 当前整理范围是打开的整篇 Markdown 笔记，尚未优先处理编辑器选区。
