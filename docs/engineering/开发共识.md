## 工程基线

- 在仓库根目录改造 `obsidian-sample-plugin-master`，插件即仓库主体（不再单设 `plugin/` 子目录）。
- 测试框架：**Vitest**。
  - 纯计算模块（`core/`、`linking/`、`changes/`）严格 TDD（red-green-refactor）。
  - UI 和 Obsidian Adapter 层不写自动化测试，靠规格中的验收场景手动验收。
- Git：每完成一个开发步骤且测试全绿就提交一次，Conventional Commits 风格 + 中文描述。
- 调试环境：仓库内建 `dev-vault/`。
  - 入库内容：fixture 笔记（同名消歧、已有链接、反向链接场景）+ 启用本插件的最小 `.obsidian` 配置。
  - 构建产物（`main.js` 等）gitignore，由 sync 脚本同步到 `dev-vault/.obsidian/plugins/ai-note-assistant/`。
- 边栏 UI：原生 TypeScript + Obsidian `ItemView`，**不引入 React**。

## 关键设计决策

- **模型输出契约**：模型返回 **JSON** 结构化 Proposal，插件端 schema 校验（ProposalValidator）后由插件渲染为给用户看的 Markdown。
  - 双链插入位置**不让模型给行号/偏移**；模型给出建议锚点句子，插件在源文中定位计算 `insertion` 范围。
- **模型端点与协议**：用户填写完整 API URL，插件原样请求，不自动拼接路径；用户必须选择与端点匹配的 Chat Completions 或 Responses API 格式。
- **过程可见性**：优先使用 SSE 流式接收并展示结构化草稿及处理阶段；流式能力不可用时允许回退普通请求，但必须明确告知用户。
- **整理依据**：Proposal 包含可回指原文的 `rationale`；不得要求、展示或伪造模型隐藏思维链。
- **版本校验**：`expectedRevision` 使用**内容哈希**——生成预览时对源文算 hash，apply 前重算比对，不一致则计划失效（不用 mtime）。
- **LinkContext 默认数量**：本地候选上限 20 篇，交给模型的候选片段上限 8 篇，最终建议展示上限 5 条，仅展示 high/medium 置信度。三个数字全部做成设置项，默认值如上，且三项都已接入实现（`localCandidateLimit` 用于本地候选，`modelCandidateLimit` 用于候选片段，`suggestionLimit` 用于建议展示）。
- **远程模型隐私**：设置页总开关默认关闭；每会话首次使用时确认一次，之后会话内直接发送；发送范围始终在边栏可见；API Key 只存 Obsidian 设置存储。
- **写回预览**：文本级 diff（新增绿色、删除红色删除线）。
- **写回位置**：默认追加到笔记末尾，可选替换选区（有选区时）或复制到剪贴板；原始内容默认保留。
