# 隐私与安全

## 默认立场

- 本地优先：笔记默认只在本地处理和保存。
- 最小读取：只读取完成当前动作所需的内容。
- Vault 边界：文件工具只能访问当前 Vault 内的相对路径。
- 明确外发：调用远程模型前，告知用户将发送哪些内容以及发送给谁。
- 可撤回：用户可以取消发送，也可以关闭远程模型功能。
- 不留秘密：API Key 只保存在 Obsidian 的设置存储中，不写入笔记、日志或提示词模板。

## 发送边界

发送到外部模型前，至少完成以下检查：

1. 当前内容是否包含用户不想外发的片段。
2. 是否确实需要远程模型才能完成动作。
3. 是否需要脱敏文件名、人员名称或其他识别信息。
4. 是否在界面中清楚显示本次发送的范围。

默认不发送整个库、无关文件、隐藏配置和插件内部数据。

思维挑战会话按轮次处理：每次发送前显示本轮会发送的笔记片段和上一轮回答。会话结束或取消后，不保留未写回的回答，除非用户明确选择保存摘要。

流式和普通请求遵守同一外发确认边界。切换为 SSE 不得扩大读取或发送范围；会话首次确认前不得建立包含笔记正文的模型请求。

过程面板可以展示处理阶段、模型可见输出和可回指原文的整理依据，但不得记录 API Key、Authorization 头、完整请求头或模型隐藏思维链。插件不要求模型返回隐藏推理过程，也不以“推理”名义伪造过程。

## 错误处理

- 网络失败、鉴权失败或模型返回无效内容时，保留原始笔记不变。
- 不把模型返回的 Markdown 直接当作可执行代码或插件配置。
- 不自动重试可能产生费用或重复发送的请求。
- 错误信息应说明下一步可操作的选择，例如重试、切换本地模型或取消。

文件工具的路径校验、同名检查和操作预览在本地完成；远程模型只接收完成当前任务所需的脱敏片段，不接收完整文件操作权限。

## 用户控制

以下操作必须由用户明确触发或确认：

- 向远程服务发送笔记内容；
- 覆盖已有笔记；
- 新建文件夹或笔记；
- 移动、重命名或归档笔记；
- 批量读取或修改多个文件；
- 删除原始记录。
